# CMS admin theme (Root System)

The admin wears its own design language, **Root System** (GDW-058): the
public site is the cedar above ground, the admin is the root network below.
Spruce-ink dark theme, bone-paper light theme, verdigris traces, ember
primaries, a mono "instrument" register for status/meta/labels, and real
self-hosted fonts. The mechanics were established by GDW-055 (which first
skinned the admin in Cedar & Circuitry; superseded visually, same wiring).
Everything rides on Payload's own theming hooks — no component forks.

## How the theme is wired

| Piece | Where |
|---|---|
| Palette + scale + editor-comfort CSS | `apps/cms/src/app/(payload)/custom.css`, imported by `app/(payload)/layout.tsx` after `@payloadcms/next/css` |
| Fonts | @fontsource packages (`@fontsource-variable/fraunces`, `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-mono`) imported in `app/(payload)/layout.tsx` — self-hosted woff2, no CDN; Next bundles the referenced files into `.next/static` |
| Global scale | `html { font-size: 15px }` (stock is 13px); Payload sizes both type and spacing in rem via `--base`, so the whole admin scales roomier. The narrow-viewport step-down is restated in `custom.css` because the unlayered override outranks Payload's own |
| Login logo / nav icon | `apps/cms/src/components/BrandLogo.tsx`, `BrandIcon.tsx` (shared SVG in `BrandMark.tsx`, Root System colorway), registered via `admin.components.graphics` + `importMap.js`; login backdrop trace in `custom.css` (`.template-minimal`) |
| Tab title, favicon | `admin.meta` in `payload.config.ts`; favicon served from `apps/cms/public/brand/favicon.svg` (the Dockerfile copies `public/` into the standalone runtime — Next does not) |
| Light/dark | `admin.theme: "all"`: account-menu preference wins, else `prefers-color-scheme` |
| Contrast regression test | `apps/cms/src/admin/theme.test.mjs` parses `custom.css` and asserts the WCAG pairs |

## How the palette works

Payload's admin colors all derive from four ramps (`--color-base-*`,
`--color-success/error/warning-*`). The light theme maps
`--theme-elevation-*` onto the base ramp directly; the dark theme maps it
onto the same ramp **reversed** (dark `elevation-0` = `base-900`). Status
ramps flip the same way. So redefining the ramps once themes both modes and
every component that follows the variable system — list views, modals,
pickers, dropzones, auth screens, version diffs.

`custom.css` is deliberately **unlayered** while all Payload styles live in
the `payload-default` cascade layer, so our rules always win. The flip side:
if Payload declares a variable per-theme inside its layer (e.g.
`--theme-overlay`), an unlayered `:root` value would override the dark case
too — restate the dark value under `html[data-theme='dark']` (see the
overlay rule in `custom.css`).

Each ramp step was generated by **luminance-matching the stock Payload value
at that step to the Root System hue family** (warm bone highlights → moss
midtones → spruce-ink shadows; verdigris success/focus, terracotta error,
amber warning), so every built-in contrast relationship is preserved or
improved. The generator lives in this repo's history as a scratch script;
the shipped hexes plus the `--gdw-*` surface/accent decisions in
`custom.css` are the source of truth, pinned by the unit test.

Known AA caveat: Payload shares `elevation-500` (secondary text) between
themes, so it cannot reach 4.5:1 on both backgrounds by construction. Stock
ships 3.94:1 (light) / 4.67:1 (dark); the granite step ships 4.05 / 4.44.
The unit test pins a ≥3.9 floor on both.

## Surface steps, ember primaries, and the instrument register

Tinting ramps alone reads as "Payload with a filter" (the GDW-055 lesson),
so the theme commits to structure (all declared as `--gdw-*` custom
properties in `custom.css`, which the unit test parses):

- **Light ("workbench daylight")**: deeper bone nav (`#e8e2d3`) → bone-paper
  page (`#f1ede2`) → near-white cards, inputs and odd table rows as raised
  surfaces.
- **Dark (default mood)**: spruce-ink page (`#0e1613`) with a panel-toned
  nav (`#131d1a`).
- **Primary buttons are ember** — the one hot action per screen. Dark theme:
  ink text on ember `#e08d4d`, hover lifts hotter; light theme: paper text
  on deep ember `#a85020`, hover deepens. Only the button color variables
  are overridden, so sizing/disabled/focus stay stock.
- **Instrument register**: nav group labels (with a verdigris trace rule),
  table headers, pills, breadcrumbs and autosave status render in tracked
  IBM Plex Mono smallcaps — the "circuitry" half of the mark.
- **Muted text lifted**: field descriptions to elevation-600, table headers
  to 550, nav group labels to 600 (stock uses 400 at ~2.8:1); the nav
  toggle's hover color is restated (layer-override side effect, see above).

Moss secondary text lands at ~3.7:1 on the bone page (vs 3.94 on stock
white); the test pins a 3.5 floor, and the description/label lifts are the
compensation. Don't deepen the page surface further without rechecking.

## Theme detection notes

Server-side, Payload resolves the first render's theme from the
`gdw-<env>-theme` cookie, then the `Sec-CH-Prefers-Color-Scheme` client
hint, then defaults to light. `withPayload` sends `Accept-CH` and the CMS
CloudFront distribution forwards all viewer headers with caching disabled,
so Chromium browsers get the right theme on first paint. Browsers without
client hints (Firefox/Safari) may flash light before Payload's client-side
provider applies `prefers-color-scheme` after hydration — cosmetic only.
Picking Light/Dark/Automatic in the admin account menu sets the cookie and
makes the choice sticky.

## Editor comfort

- On viewports ≥1200px the edit-view sidebar is capped at 380px (instead of
  33% of the window), giving the writing column the remainder.
- The Lexical body runs at 18px in the loaded Fraunces (`--font-serif`) with
  1.8 line-height, capped at 46em so lines stay under ~90 characters on wide
  monitors.
- The editor toolbar is a ruled line rather than a boxed card; it keeps a
  background so content slides under it while sticky.
- Below Payload's 1024px breakpoint the stock stacked layout is untouched.

## Verifying changes

No local CMS boot (needs Docker/Postgres), so: `pnpm --filter
@georgedallas/cms build` + `pnpm test` locally, then eyeball
https://cms-dev.georgedallas.com/admin after the develop deploy. Manual pass
checklist for theme changes, in both light and dark:

1. Login screen (logo, focus rings, error state on a bad password).
2. Dashboard, a list view with filters open, a post edit view (Compose/SEO/
   Advanced tabs + publishing sidebar).
3. A relationship picker drawer, the media upload dropzone, a version diff.
4. Narrow the window below 768px: nothing clipped or overlapping.
